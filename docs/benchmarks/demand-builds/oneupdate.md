另编译了相同 OneUpdate、ABI 46、MSVC 14.44 和 IPO 的完整 ICU/预创建字体参考外壳，大小 20,965,888 字节；最终为 18,805,760 字节，减少 10.30%。两份 SDK 纳入清单的源码输入逐项一致；参考包生成时源码尚未提交，清单如实保留 `sourceDirty=true` 和当时提交号。与已部署模板对比还包含 ABI/框架版本差异，不能将全部收益归因于某一个开关。

这些是旧版无 `installed_shell` 描述的 V3 QA 包，用真实签名计划和业务载荷重新组装。包含绝对偏移和前缀差分的新式包由工具拒绝，必须走 Worker 组装。未替换生产 Worker、签名模板或官方发布下载。

## 占用来源与改动

- **ICU 是本轮主要节省来源。** 完整数据从 10,468,208 字节、2235 项变为文字配置的 3,955,248 字节、64 项；zlib 数据从 4,570,630 降为 2,411,192 字节，另有相同的 50 字节封装。保留全部断行/分词规则和字典、规范化、大小写、emoji 与文字布局资源，逐项核验原始字节。移除其他 ICU 服务的数据，默认配置仍为 `full`。使用排序、格式化或转换服务的应用须保留完整包。
- **字体保留全部字形与字重。** 实际 OneUpdate 字体 4,084,240 字节、7552 个 Unicode cmap 条目，原有 zstd 打包保持原样。Windows 的单轴 100–900 可变字体改为按首次匹配创建字重实例，其他字体/平台沿用原路径。本次没有证明字体与窗口初始化更快：该阶段中位数反而从 33.41 变为 34.26 ms，处于本次测量波动范围，不能把延迟创建直接写成启动加速。
- **渲染保留 GPU、抗锯齿、回退、HarfBuzz 和媒体格式。** PNG 专用 API 在固定 Windows Skia 下直接调用 PNG 解码器，避免该入口引用通用解码注册表；其他 Skia 保留原注册表。实际安装器 Logo 使用 Rust 解码后传 RGBA，因此不把 PNG 入口改动列为本次主要整包收益。中间链接图中 Skia 代码约 4.13 MiB，GPU/着色器编译相关路径仍可达，不以删除这些能力换体积。

静态 IPO 归档约 1 GiB 是编译器中间表示，不是安装包。Rust 在 MSVC IPO SDK 上使用 `static:-bundle`，解决 LLVM 归档阶段丢失不透明对象符号的问题；不通过关闭 IPO 回避链接失败。

字体注册、嵌入字体提供器与字体目录查询从 `src/text/font_manager.cpp` 迁入 `src/text/embedded_fonts.cpp`，前者从 249 行降至 135 行，后者 190 行（包含注释和空行）。新模块管理字体字节寿命和字重缓存，原模块保留平台字体创建与回退职责；公开 API 不变，实际字重/匹配/像素测试覆盖这次边界调整。

## 实际启动与内存

Windows 10 22H2 x64，Ryzen 9 9950X3D，32 个逻辑 CPU。关闭本轮编译任务并恢复/停止测试虚拟机后，三个版本各预热一次，再执行 12 组交错三元对照，每组轮换启动顺序。表格为中位数，使用最终交付的生产体积包；普通桌面负载保持运行。

| 指标 | 部署模板基线 | 完整配置参考 | 优化后 | 相对部署基线 |
|---|---:|---:|---:|---:|
| 进程创建到 UI 日志点，ms | 308.10 | 301.26 | 296.80 | -3.67% |
| 已用 CPU，ms | 359.38 | 335.94 | 312.50 | -13.04% |
| 峰值工作集，MiB | 117.79 | 118.64 | 108.90 | -7.55% |
| 私有内存，MiB | 150.49 | 151.06 | 145.38 | -3.39% |

启动最小/最大值分别为：部署基线 301.51–439.48 ms、完整参考 293.71–325.85 ms、优化后 281.79–315.34 ms。相对完整配置参考，启动中位数仅快约 4.46 ms（1.48%）；该差异小，不能据此宣称显著启动加速。主要稳定收益是体积和内存。

终点为安装器既有 `ui_window_visible` 日志点，包含预检和 UI 构建；它不是第一帧提交/呈现或动画完成。CPU/内存通过进程句柄在观察到日志时采集，轮询间隔 10 ms，CPU 计时有 15.625 ms 粒度。测试使用暖缓存，不代表冷启动、Win7 启动或 GPU 帧率。启动采样不触发安装，并仅终止自己启动的 QA 进程。早期构建并发、PID 复用旧日志和中间 ICU 版本的数据均未纳入最终统计。

## 功能、画质与兼容性证据

1. **真实界面：72/72 PNG 字节完全一致。** 同一真实 OneUpdate 界面和业务包，三套主题、六种状态、100%/125%/150%/200% 强制缩放；同一验证工具链分别链接完整配置和文字配置 DLL。测试分支排空 UI 更新并等待 500 ms 动画稳定。布局原始 JSON 有 68/72 组字节相同，其余差异仅为不可见控件的过渡绘制颜色；比较器仅移除这些颜色字段，其余布局与目标样式仍须相同，全部原始哈希保留。初次未等待稳定的画面存在差异，未拿这些结果冒充通过。此证据针对本轮完整配置与精简配置，不是旧 ABI 43 模板和新 ABI 46 的画面逐字节认证；也不是 GPU/跨显示器 DPI 测试。
2. **Win7 SP1 x86 原生文字测试通过。** 1187 组 grapheme、1826 组 word、91707 组 Bidi character、770241 组 Bidi class、15 组括号回归零失败；完整/文字 ICU 的 2320 组 locale/break 组合与规范化一致，摘要 `d1c76caa537f1ef3`。实际字体九档字重的覆盖、匹配和三种字号像素一致。Win10 DirectWrite 路径也验证了九档字体与 PNG 解码结果。
3. **Win7 真实产品进程生命周期通过。** 在隔离根目录运行已部署外壳的 8.0.7 安装、同版修复，再由优化外壳升级至 8.0.8，保留用户数据；核对安装后的启动器和卸载器前缀确为优化外壳，再运行真实已安装卸载器，确认根目录移除。初期直接调用后端的测试错误地复制了测试 EXE，自检发现后作废；最终改为真实产品进程，未把早期成功日志当作最终证据。静默验收另制夹具，显式选择产品支持的 `admin_policy`，签名、载荷、Agent、健康检查保持开启；没有自动点击协议复选框。交付对比包仍保留原 `deny` 策略。虚拟机已恢复测试前保存状态，临时 Guest Control 凭据副本已删除。
4. **本轮回归：** OneUpdate 原有 88 项 Rust 测试通过；当前静态字体、交互、C API 链接、按需运行时 4/4 通过；旧工具链 Unicode/布局/字体/ICU 4/4 通过；PNG 原解码与专用解码对照通过；ABI/FFI 清单一致。此前 viewc/导出回归见 [首轮报告](README.md)。
5. **兼容性限制：** Win7 x64、macOS/Linux 未新增原生验收，其他平台保留原字体路径。固定兼容基础库的全量锁检查因本机共享基础库两个 Rust 文件哈希不同而未通过，没有修改锁或共享源码绕过它；只读导入审计对部署基线和新包均报告同一个 `TaskDialogIndirect` 的 Win7 System32 v5 参考库例外，未发现新增缺失导入。Win7 原生 UI 启动/生命周期实际通过，但不能据此写成全部静态审计通过。
