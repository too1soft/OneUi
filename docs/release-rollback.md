# 发布和回滚

## 当前允许的动作

仅生成候选、离线保存、原生测试及记录证据。不自动安装到开发者电脑，不上传，不部署生产。
此前 2.4.2 候选保留。本轮 2.4.3 候选仍未填写正式 verification、源码仍有未提交修改，因此正式发布门禁应拒绝。64 位用户延期实测只免除限定构建的原生项目，不免除已知错误、静态依赖或签名检查。
已有包全部保留。不可把本轮版本字符串相同的试验性重建包当成多次正式发版。

## 正式门禁

1. 锁定干净源码提交、工具链源码与补丁、SDK、构建参数、全部依赖。
2. 通过完整 PE 普通 / 延迟 / 转发导入和依赖闭包审计；x64 必须使用同架构系统参考。
3. 原生报告包含实际 OS / SP / 已安装补丁、程序架构、文件 SHA256、build ID、检查结果和日志。
4. 业务、更新及信任闭环通过；长稳、DPI、IME、托盘等不能用 --help 代替。
5. compat.py --release 通过后，还需 OneUpdate 服务端上传校验和签名流程；本地工具不能绕过它们。
6. 对外支持列表只展示实际通过的组合；尚待验收的平台不出现“已支持”。

Go race 在受支持的现代系统执行；Win7 原生检查单独列出，不冒充 race。
手工修改验收报告只能生成另一个文件哈希，不构成可信自动发布证据；未来 CI 还须把报告关联到受控执行与发布身份。

## 后续部署顺序（未执行）

1. 备份 OneUpdate 数据库和当前发布目录、签名数据，做只读历史制品盘点。
2. 测试环境验证追加迁移、旧接口回归、v2 签名兼容和桥接安装器。
3. 部署兼容新旧请求的服务端 / Worker，先保持新组合不可发布。
4. 发布验证过的兼容底座与修复安装器，确认旧安装迁移可恢复。
5. 按验收矩阵发布产品组合，启用 Catalog / 引导下载，再小范围灰度。
6. 监控下载、激活、精确健康确认与回滚结果，再扩大范围。

新键允许同版本多配置后，旧服务端可能无法正确理解多条记录，不能直接换回旧二进制。
回退前停止新发布，撤销 v2 激活候选，保留制品及签名；在备份恢复演练确认后执行配套数据库回滚。
不删除历史签名，不重新签名旧计划，不以全局 kill 或删除全部安装目录代替事务回滚。

## 非 GUI 人工服务升级

目标流程：校验包与签名来源 → 校验 OS/产品架构/profile → 明确并确认全部共用二进制的服务 → 持久化原状态 → 全部停止 → 备份和替换 → 恢复原运行实例 → 健康验证；失败还原。
配置、令牌和日志独立保存，不从程序包覆盖。

**WYC 的 Windows upgrade-service 已接入签名清单和全部共用实例确认，局部单元测试通过；完整服务升级和历史安装迁移仍待原生验收。**
本轮候选只用来测试兼容构建，不应直接用于升级现有生产服务。
后续实现需要明确共享二进制布局：若只升级一个实例，必须先把该实例迁到独立版本路径；不能停止一个实例后替换其他仍运行实例共享的 EXE。
