## 真实修复

1. Go 的 BCrypt 包装曾读取 GetLastError；改为使用 NTSTATUS。
2. 原版 SP1 不识别 OBJ_DONT_REPARSE；回退固定父句柄且只操作单个组件，打开重解析点后同句柄检查，保留 os.Root 边界。
3. Win7 不支持 FileFullDirectoryInfo Win32 信息类；改用同一目录句柄的 NtQueryDirectoryFile 回退。原生 TestReadDirNoFileID 从失败变为通过，不重新按路径打开。
4. OneUpdate Agent/安装器无执行权限清单，Win7 对名称的安装程序识别导致普通用户启动失败；明确 asInvoker 后 --help 通过。
5. x86 cdecl 不能使用 64 位直接系统调用路径；增加 32 位 C 调用桥、指针 pin 和重复调用测试。
6. OneUI 静态消费者曾手工列库，容易漏 FreeType；由 CMake 实际闭包生成 SDK 清单，Rust 绑定核对 manifest/架构/profile/哈希。
7. WYC GUI 固定 amd64/UCRT、按目录查 DLL 的旧脚本已替换为明确参数与锁定输入。

目录读取回退的依据：[微软信息类支持说明](https://learn.microsoft.com/en-us/windows/win32/api/minwinbase/ne-minwinbase-file_info_by_handle_class)、[NtQueryDirectoryFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntquerydirectoryfile)。

## 未销项的失败与限制

- 原先扩大运行 Go os 测试遇到测试数据未同步、符号链接权限不足及超时；不报告“完整标准库测试通过”。其中确实复现的目录枚举问题已单独修复并重测。
- 原生 VM 网络关闭。探针自建 CA 验证只能证明 TLS 逻辑，不能证明实际公网根证书或发布签名链。
- 没有 Win7 x64 同架构系统导出参考；不能拿 x86 导出表验收 x64。
- 尚无完整 GUI 本机交互截图、100 次托盘关闭恢复记录、完整安装更新链路或长稳数据。
- 测试 VM 上的用户和管理员权限场景仍须分别覆盖；不得为了通过测试降低系统安全设置。
- 所有正式发布 verification 留空；不人工填 passed 消除门禁。
