## 取得测试配置后的核对（2026-09-09 15:41 起）

- 新签名探针 `public-tls-probe-x86-signed-r2.exe`，最终 SHA256 为 `c8e6d9bee59d7e5dcf0bc45104dc6c1412934eabb7d0c32263aeb87216dbe5fe`。使用现有证书和 SHA256/RFC3161 时间戳；没有导出私钥。
- 现代主机原生验签通过。原版 Win7 SP1 x86（6.1.7601，SP1）的同一文件通过直接调用 `WinVerifyTrust` 检查，33.439 秒后返回 `0x800b0109 / untrusted_root`。开启证书吊销检查，没有忽略证书错误，也没有安装根证书。此结果是验收失败，不能改标为通过。
- 证据在 `evidence/native-authenticode-x86-r1`，同时记录检查程序及被检文件哈希。检查程序 SHA256 为 `eb7999b852b6b3be04a3f2d4b5c6ef9b863f61df24e78ccd908cf6e3e00075be`。PowerShell 2.0 检查也显示不信任根证书，但其进程存在超时，故另用不依赖 PowerShell/WMI 的原生检查交叉确认。
- 新增原生签名诊断源码 `runtime/go/cmd/authenticode-probe`；Win7 ABI 尺寸和仅零返回值才表示成功的测试通过。原生检查依据 [Microsoft WinVerifyTrust](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/nf-wintrust-winverifytrust) 和 [WINTRUST_DATA](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/ns-wintrust-wintrust_data)，使用原版 SP1 已支持的结构，未引入补丁前提。
- OneUpdate `/healthz` 和公开 Catalog 返回过 200；新增 `/api/public/v2/apps/wyc/downloads` 返回 404。期间也观察到 HTTPS EOF，不能把一次基础探针成功写成安装下载全链路通过。
- 增加 `server/cmd/compat-preflight`：显式配置文件、指定应用范围、只读事务、查询超时、错误脱敏；不加载服务端或执行迁移。测试库端口拒绝 TLS，检查在数据库认证前停止；没有通过明文回退读取远程数据库。仍可继续使用此前隔离 PostgreSQL 做本地迁移测试。
- Foundation Go 测试（含新原生探针 ABI 测试）和只读预检工具测试通过。本次没有生成新的正式产品包，没有部署测试站，也没有更改原版 VM 信任库。
